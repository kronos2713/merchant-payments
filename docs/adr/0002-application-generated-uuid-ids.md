# 0002. Generate UUID v4 ids in the application

Date: 2026-10-11
Recorded retrospectively; decided 2026-10-01.
Status: Accepted

## Context

Merchant and payment request ids appear in URLs, for example
`/merchants/{merchantId}/payment-requests/{id}`. A payer receives a payment
request id and uses it to pay. Ids also need to be known early: Phase 2 adds
idempotency keys and an outbox, and both need to reference a record before it
is inserted.

At the bank I work with Oracle sequences: the id only exists after the insert,
and consecutive numbers make it easy to guess the next record.

## Decision

Every entity gets its id from `UUID.randomUUID()` (UUID v4) inside its static
factory: `Merchant.register(...)` and `PaymentRequest.create(...)`. The columns
are `uuid primary key` with no database default, so the database never invents
an id.

`equals` and `hashCode` are based on the id. Because the id is set in the
factory, an entity is equal to itself before and after it is saved.

### Alternatives considered

- **Database sequence (`bigserial`).** Smallest and fastest index, but ids are
  guessable in a public URL, and they only exist after the insert.
- **UUID generated by the database (`gen_random_uuid()` default).** Not
  guessable, but the id is still unknown until the insert, which brings back the
  `equals` problem for new entities.
- **UUID v7 (time-ordered).** Not guessable, and inserts land at the end of the
  index instead of at random places. It needs its own generator, since
  `UUID.randomUUID()` produces v4. I chose v4 to keep the MVP simple.

## Consequences

- Ids can't be enumerated from a URL. That is not access control: Phase 3 still
  needs authentication and ownership checks.
- Any code can create a fully identified entity without touching the database,
  which unit tests and the Phase 2 outbox rely on.
- A UUID is 16 bytes instead of 8, and random v4 values spread inserts across
  the primary key index. `payment_requests` is the high-volume table, so moving
  it to UUID v7 is on the post-MVP hardening list.
